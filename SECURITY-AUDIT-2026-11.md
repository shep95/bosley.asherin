# security audit — bosley.asherin.com (2026-11-18)

source: external header scan (80/100) plus a review of `vercel.json`,
`index.html`, the build and the service worker.

| # | finding | severity | status |
|---|---------|----------|--------|
| 1 | CSP `style-src 'unsafe-inline'` in the header and the meta copy (A03 · CWE-79) | medium | fixed |
| 2 | `Access-Control-Allow-Origin: *` on every response (Vercel's default) (A05 · CWE-942) | info | fixed |
| 3 | no `Origin-Agent-Cluster` | low | added |
| 4 | service worker controls the origin (A05 · CWE-16, informational) | info | reviewed |

## what changed

- `style-src 'self'` in `vercel.json` and `index.html`; no `'unsafe-inline'`
  remains anywhere in the policy.
- three dependencies wrote `<style>` tags at runtime, which a strict policy
  blocks. `scripts/cspStylesPlugin.ts` (the same plugin asherin.com uses)
  rewrites them at build time:
  - sonner's injected CSS is dropped and its published `styles.css` is
    imported in `src/main.tsx`;
  - Radix ScrollArea's viewport rules live in `src/index.css`;
  - `react-style-singleton` (dialog scroll lock) uses a constructed
    stylesheet (`adoptedStyleSheets`), which CSP does not govern.
  the plugin fails the build if any of those libraries changes shape, so an
  upgrade cannot silently reintroduce inline styles.
- `Access-Control-Allow-Origin: https://bosley.asherin.com` replaces `*`.
- `Origin-Agent-Cluster: ?1`.

## service worker

generated by `vite-plugin-pwa` from this repo, registered by the external
`/registerSW.js` (no inline script), served `no-cache`, scope `/`.
`worker-src 'self'` stops any other origin's worker. no change needed.

## verified

- `npm run build` and both `tsc` projects pass.
- production build served with the `vercel.json` headers in chromium: 11
  routes with no CSP violations and no console errors; injected inline event
  handlers blocked.
- with placeholder Supabase settings the landing page and the sign-in dialog
  render with the strict policy: the dialog opens, scroll lock applies
  (`body` overflow hidden via an adopted stylesheet), zero CSP messages.
